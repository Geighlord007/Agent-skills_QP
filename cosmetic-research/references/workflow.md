# Cosmetic Research Workflow

## 目标

从一个化妆品成分出发，经过多维度调研、冲突消解、逐节组装、自动引用校验与质量评估，产出一份结论清晰、来源可追溯的成分调研报告并交付 DOCX。

> **证据分级、利益相关方立场标注与 6 条一票否决红线**统一以 `references/rubric.md` 为单一信源，全流程严格遵守。

---

## 工作流总览

```text
阶段 A：调研与数据收集（只做调研，不写报告）
  Step 0: 理解问题
  Step 1: 启动 6 个主题 Thread 子代理并行调研（覆盖 10 个核心维度）
  Step 2: 冲突消解
  Step 2.5: 向用户汇报调研结果，等待确认

阶段 B：报告组装与交付（用户确认后才开始，不再做大范围调研）
  Step 3: 逐节组装 report.md（每节只读对应 Thread，写完一节保存一节）
  Step 3.5: 完整性检查 + 运行 tools/url_verify.py 校验引用（门控）
  Step 4: 按 references/rubric.md 质量评估并存入 eval/
  Step 5: 定点修复并交付 DOCX 至 output/
```

---

## 阶段 A：调研与数据收集

### Step 0: 理解问题

拿到选题后先做一轮快速检索：
- 确认基本身份：INCI 名称、CAS 号、来源、主要功效类别。
- 明确用户决策场景（研发技术可行性 / 投资机会 / 品类竞品）。
- 识别潜在关键风险（如某主要市场的特殊监管壁垒）。

向用户汇报初步理解与调研重点，确认后启动 Step 1。

### Step 1: 启动 6 个主题 Thread 并行调研

**全部 6 个主题 Thread 必跑**，完整覆盖原 10 个分析维度，避免按成分类型提前跳过（“无数据”本身即市场空白或研究空白）。合并高耦合维度可降低重复检索与上下文碎片化。

#### Thread 列表与落盘命名（严格零填充，不含斜杠）

| # | 输出文件 | 覆盖维度与核心调研内容 |
|---|----------|------------------------|
| T01 | `drafts/T01_基础与配方.md` | **基础信息 + 辅料配方**：INCI（中英）、CAS/EC 号、生物/化学来源、分类、工业与化妆品用途；最佳配方条件（pH/温度/辅因子/浓度）、常用辅料兼容性、稳定性与货架期 |
| T02 | `drafts/T02_作用机理.md` | **作用机理**：生化机制、关键通路与靶点、与同功效竞品机制对比、近 3 年研究突破（PubMed） |
| T03 | `drafts/T03_专利与公司.md` | **专利布局 + 公司关系**：EPO/USPTO/CN/JP/KR 专利号、申请人、当前权利人、申请日/授权日、权利转移；SEC EDGAR / 官方公告中的投资、并购、授权、合资关系 |
| T04 | `drafts/T04_临床证据.md` | **临床证据**：PubMed RCT/split-face/open-label、PMID/DOI/标题/作者/期刊/设计/样本量/时长/量化结果、系统综述；严格区分同行评审 vs 商业宣传 |
| T05 | `drafts/T05_商业与竞品.md` | **商业化现状 + 竞争格局 + 用户体验**：使用该成分的品牌与产品线、规格/功效/价格/在售状态（活跃/退出/萎缩）；至少 5 种同功效主流竞品对比与差异化定位；电商/社媒正负面评价原文与时效性 |
| T06 | `drafts/T06_监管状态.md` | **监管状态**：中国 NMPA（已使用原料目录）、美国 FDA、欧盟 CosIng、韩国 MFDS、日本 MHLW 官方数据库查询结果、监管框架、准入门槛与政策变化（区分官方记录 vs 品牌声称） |

#### 子代理 Prompt 模板

```text
你是化妆品原料调研助手。

【调研线程】{thread_id} - {thread_name}
【目标成分】{ingredient_name}（INCI: {inci}, CAS: {cas}）
【用户角色】{user_role}，重点关注 {key_focus_areas}
【研究背景】
- 研究目的：{specific_question}
- 已知信息：{known_facts}

请完成该线程对应的全部维度调研，并将结果写入 drafts/{thread_filename}：
1. 输出结构化调研结果，末尾单列「结论摘要」与「数据缺口/待验证」。
2. 每条事实注明一手来源（PMID / 专利号 / 官方数据库或官网 URL）与时间。
3. 每条结论标注置信度（高/中/低），品牌商业宣传须标明“来源为利益相关方”。
4. 不同来源说法矛盾时明确标注，不要自行抹平。
5. 只收集和整理数据，不要写正式报告。
```

#### 结果处理与工具选择

- **有数据** → 进入冲突消解；**数据稀疏** → 标注“该领域数据有限”；**无数据** → 写入“未检索到相关信息（可能代表市场或研究空白）”。
- **检索能力优先级**（工具无关，按宿主实际可用工具调度）：
  1. 网页搜索（宿主内置 WebSearch 或同仓 `exa-search`）
  2. 网页抓取（读取 PubMed、Google Patents、SEC EDGAR、品牌官网）
  3. 专业文献/数据库技能（如同仓可用的 `pubmed-database` / `literature-search`）
  4. 交互式浏览器（用于必须 JS 渲染和页面交互的官方监管数据库，见文末指南）

### Step 2: 冲突消解

收集全部 6 个 Thread 后，主动交叉比对冲突，**不可跳过**：

| 冲突类型 | 常见信号 | 权威仲裁源 |
|----------|----------|------------|
| 专利权人 | 品牌宣传说 X，专利库说 Y | Google Patents / EPO / USPTO |
| 公司关系 | 新闻稿称“收购”，财报称“参股/授权” | SEC EDGAR / 交易所公告 |
| 时间线 | PR 称 2010，论文发表于 2015 | 同行评审论文发表日 vs 研究完成日 |
| 监管状态 | 品牌称“已获批”，目录查无记录 | 各国官方监管数据库 |
| 疗效声称 | 品牌称“临床证实”，实为小样本未发表 | PubMed 原始同行评审论文 |
| 市场状态 | 第三方仍有链接，官网已下架 | 品牌官网 + 实时在售状态 |

对每处冲突派发定向核验：可消解则采用权威源并注明差异；仍无法消解则标注 `⚠️ 不同来源说法矛盾，待核实`。

### Step 2.5: 调研阶段收尾

1. 更新 `progress.md`，记录阶段 A 完成状态、核心发现与未决冲突。
2. 向用户汇报：3–5 条关键发现、未解决的冲突、数据稀疏的维度。
3. **等待用户确认后，进入阶段 B。**

## 阶段 B：报告组装与交付

### Step 3: 逐节组装 `report.md`

**写作铁律**：
- 每写一节只读取对应 Thread 文件，写完立即增量保存到 `report.md`。
- 每个二级标题下必须有实质分析叙述（表格是叙述的补充，不可用空标题或单表替代）；禁止写“详见 drafts/”等占位符。
- 结论先行、中立克制、来源必标（`[PMID xxxxxxxx]`、`[专利号]`、`[SEC EDGAR, YYYY-MM-DD]`、`[官方数据库/URL]`），证据分级与红线严格遵循 `references/rubric.md`。

#### 报告章节映射（统一编号：执行摘要 + 一至十）

| 报告章节 | 读取 Thread | 核心产出 |
|----------|-------------|----------|
| **执行摘要** | T01–T06 结论摘要 | 3–5 条量化核心发现 + 技术/商业/监管 go/no-go 判断 + 适合进入的公司类型（若有影响结论的冲突标 `⚠️`） |
| **一、原料基本信息** | T01, T03 | 基础参数表（INCI/CAS/EC/来源/分子量/用途）；专利与公司变迁时间线（以专利局与 SEC 为准，未披露条款标 `⚠️ 未公开披露`） |
| **二、作用机理与配方条件** | T02, T01, T05 | 3–5 步生化通路（附 PMID）；≥5 种同功效竞品机制对比表与差异化分析；配方条件表（pH/温度/辅因子/浓度/兼容性）；近 3 年研究突破 |
| **三、临床证据** | T04 | 已发表临床研究一览表；全部“高置信度”同行评审研究逐篇展开（标题/作者/期刊/PMID/DOI/设计/样本量/时长/分组/量化结果/局限性 + PubMed 链接）；商业/未发表数据单列并标注利益相关方与低置信度；系统综述；核心论断证据状态总结表（✅/❌） |
| **四、学术文献汇总** | T04, T02 | 全部有 PMID 的临床与机制论文总表（`# | 标题 | 期刊 | 年份 | PMID | 关键结论`） |
| **五、竞争格局与产品现状** | T05 | 已上市品牌/产品表（含在售状态）；多渠道价格体系表；市场份额/渗透率/认知度对比（机理对比引用「二、作用机理」避免重复）与差异化定位；消费者正负面反馈与原文；品牌现状综合判断（基于事实） |
| **六、监管状态** | T06 | 必覆盖中（NMPA）/韩（MFDS）/美（FDA）/欧（CosIng）/日（MHLW）5 大市场（主管机关、框架、查询结果、准入路径、门槛与新规）+ 5 国对比表 + 合规路径与周期建议 |
| **七、数据库查询指南** | T06 | 各官方数据库网址与实际查询结果复现表 |
| **八、商业化机会与风险评估** | T05, T06, T03 | 3–5 个具体机会点（附证据来源）；3–5 个具体风险点（监管/技术/商业/数据 + 影响程度）；适合进入的公司类型及前提条件 |
| **九、待验证事项** | T01–T06 数据缺口 | 编号列出无法确认的事项、所属维度与建议验证方式 |
| **十、参考文献** | T01–T06 全部来源 | 编号汇总所有 PMID、专利号、官方 URL、新闻源（`编号 | 类型 | 引用内容 | 链接/编号`） |

QA 前在 `drafts/` 保存一份带日期快照（如 `drafts/{YYYY-MM-DD}-{成分名}-report-preqa.md`）。

### Step 3.5: 完整性检查与引用自动校验（交付前门控）

1. **运行自动校验脚本**（必须执行）：
   ```bash
   python tools/url_verify.py --deep --output eval/url_report.md report.md
   ```
   - 核查所有 `fail` / `timeout` / `error` 以及 `--deep` 标题不匹配项，修复死链、错误 PMID 或错误专利号。
   - 对反爬官方站点产生的 `manual_check` 项，结合交互式浏览器记录确认其有效性。
2. **结构与数据门控检查**：
   - [ ] 执行摘要含 go/no-go 综合判断与适用公司类型
   - [ ] 每个章节均有叙述段落，无占位符或空节
   - [ ] 临床章节完整展开 T04 中全部高置信度研究
   - [ ] 竞品对比 ≥5 种同功效成分；监管状态完整覆盖中/韩/美/欧/日 5 大市场
   - [ ] 参考文献 ≥10 条（不足则注明原因），且关键论断均有 PMID/专利号/官方 URL 支撑
   - [ ] 品牌来源声称均已标注利益相关方；跨章节无未标注矛盾

任意检查项不通过，回退 Step 3 定点补齐后再重检。

### Step 4: 质量评估

门控通过后，按 `references/rubric.md` 独立检查 6 条红线并对 D1–D7 逐项打分，评估结果保存至 `eval/eval_report.md`。

### Step 5: 定点修复与 DOCX 交付

1. 仅针对 `eval/eval_report.md` 识别出的问题按节定点修改 `report.md`，修订后对受影响维度复评。
2. **DOCX 转换**：
   - 优先复用同仓 `docx` skill 生成专业排版的 Word 文档；若使用自定义 `python-docx` 脚本，确保：`##`/`###` 映射为 Heading 2/3、粗体与表格边框完整、引用块浅黄底色（`#FFF3CD`）、保留 `⚠️`/`✅`/`❌` Unicode、无残留 Markdown 原始符号且表格不截断。
   - 终稿输出至 `output/{YYYY-MM-DD}-{成分名}-调研报告.docx`。
3. 若用户需要投递至飞书/邮件等外部渠道，请使用独立通知工具并从环境变量读取凭证与接收方 ID（切勿在工作流或脚本中硬编码个人 ID/Token）。

## 官方数据库访问指南

多数官方监管数据库为 JS 渲染的单页应用（SPA），直接拼接查询 URL 往往失效，需使用宿主可用的交互式浏览器：打开主页 → 定位搜索框 → 输入 INCI/CAS 检索 → 记录查询日期与结果。

| 数据库 | 地址 | 访问方式 |
|--------|------|----------|
| CosIng (EU) | `https://ec.europa.eu/growth/tools-databases/cosing/` | 交互式浏览器搜索 |
| NMPA (China) | `https://www.nmpa.gov.cn/datasearch/home-index.html` | 交互式浏览器搜索 |
| FDA Cosmetics (US) | `https://www.fda.gov/cosmetics` | 主页导航 / 检索 |
| MFDS (Korea) | `https://www.mfds.go.kr` | 交互式浏览器搜索 |
| KCA (Korea) | `https://www.kca.or.kr` | 行业标准/原料信息 |
| MHLW (Japan) | `https://www.mhlw.go.jp` | 医药部外品/化妆品标准检索 |
| SEC EDGAR | `https://www.sec.gov/edgar/searchedgar/companysearch` | 公司公告与年报检索 |
| PubMed | `https://pubmed.ncbi.nlm.nih.gov/{PMID}/` | URL 直接抓取 / E-utilities |
| Google Patents (EPO/USPTO/CN/JP/KR) | `https://patents.google.com/patent/{patent_number}` | URL 直接抓取 |
| INCIDecoder / EWG Skin Deep | `https://incidecoder.com` / `https://www.ewg.org/skindeep/` | 辅助检索（非官方仲裁源） |
