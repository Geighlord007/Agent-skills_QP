# 会议转写与纪要方法论

本文档是 video-transcribe 处理会议类媒体的完整规范，转写清洗与纪要逻辑与
[[qwen-asr-transcribe]] 同源并针对本 skill 的场景（视频会议、纯音频会议、游戏误识别排除）做了扩展。

## 一、会议判定（先判定，再处理）

按以下顺序给媒体定性，**判定依据要写进产出物**，禁止只凭文件名：

1. 语音存在性：ffmpeg 静音检测（silent_ratio > 0.95 且时长短 → 大概率无语音）。
2. 画面内容：Qwen-VL 分类或 `understand` 整段细读（腾讯会议/WPS 共享/多人头像 → 会议；
   游戏界面 → 排除）。
3. **转写稿内容 sanity check**：ASR 会把游戏音乐、环境音误识别成"转写稿"。判定标准：
   语句是否为连贯的人类对话（有称呼、有来有回），还是歌词/碎片（如 NBA 2K 录音转出的
   "wildest applause" 歌词片段）。游戏录像即使有"转写稿"也不是会议。

## 二、校对清洗（转写稿 → 校对版）

对每一份要产出纪要的转写稿执行。长稿（>40KB）派子代理并行执行，每个子代理的指令必须
包含本节全文。产出一律写新文件 `<会议名>_校对版.md`，**原稿永不覆盖**。

1. **结构冻结**：`**[HH:MM:SS] 说话人N：**` 块的时间戳、编号、顺序一律不动，逐块处理。
   完工后用脚本校验块序列与源稿一致（时间戳序列 diff 为 0）。
2. **专名统一**：先通读列出人名/公司/品牌/术语对照表，再逐块替换。同稿异拼是典型信号
   （毕赤酵母写成 B是/B氏/B式/B4、溶氧写成容量/荣耀/农药）。无法确认的专名**保留原文**，
   列入存疑清单，禁止瞎猜。可用公开资料核验（如公司全称、人职称）并注明依据。
3. **去冗**：删孤立语气词（呃、嗯、啊）、修口吃重复（"我我我"→"我"），保留口语风格与
   原意，不改写句子。独立成句的应答"嗯""好的"保留。
4. **修标点与大小写**：英文稿的中文句号「。」改回 `.`，句首大写，i→I，品牌与学名按官方
   写法（Aspergillus niger、bLF、SDS-PAGE、GRAS、Komagataella phaffii）。
5. **删幻听**：整句/整段原文重复的模型 artifact 删到只剩一遍，保持上下文连贯。
6. **说话人实名化**（多人必做）：依据自我介绍、主持人串场提名、互相称呼、画面"正在讲话"
   提示、跨会议同角色交叉比对，把 `说话人N：**` 替换为 `姓名（机构）：**`。无法确认的
   保留 `说话人N`，纯属发音猜测的姓名列存疑。校对版头部加人名对照表与专名对照表。
7. **转写空洞标注**：源音频长但转写覆盖不全时（静音/无语音段），在校对版头部注明覆盖
   区间与空洞位置。
8. **收尾报告**：改动统计、对照表、存疑清单。

## 三、会议纪要提取（校对版 → 纪要）

产出 `<会议名>_会议纪要.md`，结构固定：

```
# <会议名> 会议纪要
## 会议信息        （时间〔源文件时间+内容互证〕、时长、来源文件、转写引擎）
## 参会人          （姓名（机构），未知标注）
## <议题一>…<议题N> （按议题分节，每节 3-6 句，长会议按工艺/业务环节分节）
## 结论与行动项     （谁、做什么、时间线）
## 存疑清单        （编号列出，供用户按现场记忆核对）
```

质量标准：
- 主题从内容提炼（如"瀚海培养基工艺对比会"），可修正自文件名的占位名。
- 参会人识别与校对版实名化结果一致；画面成员列表线索可用但不得强行对应发言。
- 数字类关键信息（配比、OD 值、升数、价格）必须忠实于转写稿，不得推算补齐。
- 存疑清单必须存在：没有存疑项的纪要意味着清洗不彻底或没做实名化核对。

## 四、docx 装配（纪要 → 带截图的 Word 文档）

用 `scripts/make_meeting_docx.py`（python-docx；机器有 .NET SDK 时可改用 docx skill 的
C# 管线，禁止 pandoc）。规范：

- 命名 `会议纪要_<主题短语>_<YYYYMMDD>.docx`，日期取源文件时间，不留 v1/v2 迭代名。
- 结构：居中大标题 + 元信息行（日期·时长·来源·转写引擎）→ 纪要正文 → 「关键画面截图」节。
- 有画面的会议嵌 5 张左右截图，**按内容选图**（`engine.select_key_frames`：清晰度优先 +
  感知去重），禁止无脑均匀抽帧；纯音频会议不嵌图。截图先 PIL 压缩（RGB、最长边 1100、
  质量 62）再嵌入。
- 页眉（会议名）+ 页脚页码；低饱和单一色相（默认 2F5D62 青灰）。
- 校对版转写如需出 Word 版，排版按 [[qwen-asr-transcribe]] 的「导出 docx 的排版要点」
  （发言块标签加粗着色、长发言拆段、延续段缩进）。

## 五、并行与交互

- 批量处理时按文件大小分组派子代理（单代理 ≤80KB 转写稿），每个子代理的指令必须携带
  第二节全文 + 该文件的背景线索（画面分类结果、已知人名），并要求返回：输出路径、
  主题一句话、参会人、存疑数。
- **执行前必须把方案交给用户确认**（见 SKILL.md 工作流）：逐文件的处理计划、命名、
  嵌图数量，用户点头后才开始 ASR/校对/docx 等重处理。
