# Cosmetic Research Workflow

## 目标

从一个化妆品成分出发，经过多维度调研、冲突消解、证据组织，产出一份结论清晰、来源可追溯、可经受追问的成分调研报告，通过质量评估后交付 DOCX。

---

## 来源标注规则

每个数据点和引用须标注：**谁说的、什么时候说的**。在此基础上：

- **品牌的效果声明须标注立场。** 来源对所述内容有商业利益时（如品牌宣称自家产品效果），必须标注"来源为利益相关方"。此类声明不得作为关键论断的唯一支撑，除非有独立来源交叉验证。
- **硬事实以一手源为准。** 专利信息以 EPO 为准，监管状态以官方数据库为准，临床数据以 PubMed 原文为准。
- **无 PMID、无专利号、无官方 URL 的来源不得支撑关键论断。**

---

## 工作流总览

整个流程分为两个明确分离的阶段：

```
阶段 A：调研与数据收集
  Step 0: 理解问题
  Step 1: 启动全 Thread 调研（10 个子代理）
  Step 2: 冲突消解
  → 向用户汇报调研结果，等待确认

阶段 B：报告组装（用户确认后才开始）
  Step 3: 逐节组装报告（每节读取对应 Thread，写完一节保存一节）
  Step 3.5: 完整性检查（门控，不通过则回退补充）
  Step 4: 质量评估
  Step 5: 修复与交付
```

**关键原则**：阶段 A 只做调研，不做写作。阶段 B 只做写作，不再做调研。两阶段之间有用户确认节点，确保组装前调研数据已完整。

---

## 阶段 A：调研与数据收集

### 0. 理解问题

拿到用户选题后，不要直接开跑。先做一轮 web research，目的是：

- 建立对该成分的基本认知：INCI 名称、CAS 号、来源、主要用途。
- 识别用户问题背后的真实决策场景：研发想评估技术可行性？投资想看市场机会？品类想看竞品？
- 发现用户可能未意识到的关键维度（如该成分在某国有特殊监管壁垒）。

研究完成后，向用户汇报你的理解。用户确认后，进入 Thread 调研。

### 1. 启动全 Thread 调研

**全部 10 个 Thread 必跑，不按成分类型提前排除。**

原因：植物提取物也可能有专利布局，合成物也可能涉及公司关系（烟酰胺离不开 L'Oréal 的讨论），任何成分都可能有配方兼容性问题。"没有数据"本身就是重要发现。

#### Thread 列表

| # | Thread | 调研内容 |
|---|--------|---------|
| T1 | 基础信息 | INCI, CAS, 来源生物/化学, 分类, 工业用途, 化妆品用途, 功能分类 |
| T2 | 作用机理 | 生化机制, 关键通路和靶点, 与竞品机制对比, 配方条件(pH/温度/辅因子), 近3年突破 |

| T5 | 商业化现状 | 使用该成分的品牌和产品线, 规格/功效/价格, 品牌市场状态(活跃/退出), 官网/电商在售情况 |

| T7 | 用户体验 | 消费者评价(Amazon/社交媒体), 正面/负面反馈分类, 典型原文, 来源和时效性 |
| T8 | 监管状态 | NMPA(已使用原料目录), FDA, CosIng, MFDS, MHLW, 区分官方数据库vs品牌声称, 各市场准入门槛 |
| T9 | 公司关系 | SEC EDGAR 投资/并购, EPO 专利权转移, PRNewswire 公告, 区分收购/投资/授权/合资 |
| T10 | 辅料/配方 | 最佳配方条件, 与常用化妆品辅料兼容性, 稳定性和货架期, 特殊 pH/温度/辅因子需求 |

#### Thread 执行方式

每个 Thread 启动一个子代理，使用以下 prompt 结构：

```
你是化妆品原料调研助手。

【调研线程】{thread_name}
【目标成分】{ingredient_name}（INCI: {inci}, CAS: {cas}）
【用户角色】{user_role}，重点关注 {key_focus_areas}
【研究背景】
- 研究目的：{user_role} 想知道 {specific question}
- 重点关注：{3 key questions}
- 已知信息：{any facts user already shared}

请调研以上内容。

【输出要求】
1. 结构化调研结果
2. 每条信息注明来源（PMID / 专利号 / 官网URL / 数据库名称）
3. 每条结论标注置信度（高/中/低）
4. 多个来源说法矛盾时明确标注
5. 不要写报告，只收集和整理数据
```

每个 Thread 的结果保存到 `drafts/T{N}_{thread_name}.md`。

#### Thread 结果处理

| 结果 | 处理 |
|------|------|
| 有数据 | 进入冲突消解 |
| 数据稀疏 | 标注"该领域数据有限"，进入报告 |
| 无数据 | 写入报告"未检索到相关信息" = 市场空白或研究空白 |

3. **补充工具**（仅当首选不够时）：

| 工具 | 命令 | 状态 |
|------|------|------|

| 微信公众号 | `miku_ai.get_wexin_article('keyword', 10)` | 可用 |
| 小红书 | — | 当前 offline |
| 微博 | — | 当前 offline |

### 2. 冲突消解

收集全部 Thread 结果后，主动寻找冲突。**Do NOT skip.**

#### 常见冲突模式

| 冲突类型 | 信号 | 权威来源 |
|----------|------|----------|
| 专利权人 | Marketing says X, EPO says Y | EPO (patents.google.com) |
| 公司关系 | Press release says "acquired", SEC says "investment" | SEC EDGAR |
| 时间线 | PR says 2010, paper says 2015 | Peer-reviewed publication date |
| 监管状态 | Brand says "approved", NMPA says "not in directory" | Official agency database |
| 疗效声称 | Brand says "clinically proven", only small study | PubMed original paper |
| 市场状态 | Amazon shows listing, brand website is dead | Brand website + current availability |

#### 消解流程

For each conflict:
1. Spawn a focused verification subagent to check authoritative source
2. Resolvable → use authoritative source, note discrepancy
3. Unresolvable → mark: `⚠️ 不同来源说法矛盾，待核实`

#### 验证模板

**PMID 验证**：
```
请验证以下文献信息：
- 论文标题：{title}
- 正确 PMID：
- 作者（完整列表）：
- 期刊、年份、卷期页码：
- DOI：
- 发表日期 vs 研究完成日期（是否不同）
- 关键结论摘要（1-2句）
以你查到的为准。
```

**专利验证**：
```
请验证以下专利信息：
- 专利号：{patent_number}
- patents.google.com 上查到的当前权利人：
- 原申请人：
- 申请日、授权公告日：
- 权利要求范围摘要：
以 EPO/USPTO 数据为准，不以品牌宣传为准。
```

### 2.5 调研阶段收尾

冲突消解完成后：

1. 更新 `progress.md`，记录调研完成状态和所有已发现的冲突。
2. 向用户汇报：调研完成，列出关键发现（3-5 条）、已发现但未解决的冲突、数据稀疏的 Thread。
3. **等待用户确认后，才进入阶段 B（报告组装）。**

---

## 阶段 B：报告组装

**⚠️ 前提：用户已确认调研结果，阶段 A 全部完成。**

### 3. 逐节组装报告

#### 核心原则

1. **每写一节，只读该节对应的 Thread 文件**——不要一次性读取全部 drafts/。
2. **写完一节立即保存**——不要等全文写完。
3. **不存在只含标题或只含表格的章节**——每个二级标题下必须有分析叙述。
4. **不允许占位符**——不要写"详见 Thread 数据"或"此处应包含"。要么写完整内容，要么标注 `⚠️ 该领域数据有限`。

#### 🔥 反截断指令

这是调研的最终交付物。不要为了节省篇幅而截断或摘要化。

**DO:**
- ✅ 每个章节写完整内容，不是大纲或要点
- ✅ 将 Thread 数据转化为叙述文本 + 结构化表格
- ✅ 为每个关键论断标注来源（PMID / 专利号 / URL）
- ✅ 有数据就展开写，没数据就明确标注"未检索到相关信息"

**NEVER:**
- ❌ 只留标题不写内容
- ❌ 用一个表格代替整个章节（表格是叙述的补充，不是替代）
- ❌ 写"详见 drafts/ 目录"——Thread 数据必须融入报告正文
- ❌ 跳过任何章节——没有数据的维度也要写"未检索到相关信息，这可能意味着市场空白或研究空白"

#### Thread → 报告章节映射

| 报告章节 | 读取哪些 Thread | 提取要点 |
|----------|----------------|----------|
| 执行摘要 | 全部 Threads 的结论部分 | 综合判断，不是数据罗列 |
| 一、原料基本信息 | T1, T3, T9 | 基础参数表 + 专利时间线 + 公司变迁 |
| 二、作用机理 | T2, T10 | 机制叙述 + 竞品对比 + 配方条件 |
| 三、临床证据 | T4 | 研究一览表 + 每项研究详情 |
| 四、学术文献 | T4, T2 | 全部相关论文汇总表 |
| 五、竞争格局与产品 | T5, T6, T7 | 产品表 + 竞品对比 + 用户反馈 |
| 六、监管状态 | T8 | 逐市场覆盖 + 对比表 |
| 七、数据库查询指南 | T8 | 各数据库查询结果 |
| 八、商业机会与风险 | T5, T6, T8, T9 | 机会 + 风险 + 公司类型建议 |
| 九、待验证事项 | 全部 Threads | 各 Thread 的数据缺口汇总 |
| 十、参考文献 | 全部 Threads | 所有 PMID、专利号、URL 汇总 |

#### 逐节组装流程

按以下顺序逐节写作。每写完一节，保存 `report.md`，再开始下一节。

##### 第一节：执行摘要

读取：全部 Thread 文件的"结论"或"总结"部分。

**分析深度：**
- 3-5 条核心发现，每条 2-3 句，必须包含量化数据或明确判断。
- 综合判断段落：从技术可行性、商业前景、监管合规三个角度给出 go/no-go 意见。
- 明确指出该成分适合什么类型的公司进入（而非泛泛的"有潜力"）。
- 如果有未解决的数据冲突影响核心判断，在摘要中标注 `⚠️`。

##### 第二节：原料基本信息

读取：`drafts/T01_基础信息.md` + `drafts/T03_专利布局.md` + `drafts/T09_公司关系.md`

**分析深度：**

1. **基础参数表格**：
   从 T1 提取 INCI（中英文）、CAS、EC 编号、来源生物/化学、分子量（如已知）、主要用途、分类。每项标注来源。

2. **专利背景与公司变迁**：
   从 T3 提取核心专利信息，按时间线组织（谁在什么时候申请了什么专利、权利如何转移）。
   从 T9 补充公司关系的商业侧信息（投资、并购、授权）。
   时间线中每个节点标注来源：`[EPO专利号]`、`[SEC EDGAR, date]`、`[新闻源, date]`。
   对未公开披露的商业条款标注 `⚠️ 未公开披露`，不得推测具体金额。

3. **如 T1 与 T3/T9 信息有冲突**（如专利权人描述不一致），以 T3 的 EPO/USPTO 数据为准，并在文中标注冲突和选择的理由。

##### 第三节：作用机理

读取：`drafts/T02_作用机理.md` + `drafts/T10_辅料配方.md`

**分析深度：**

1. **功效机制叙述**：
   用 3-5 步描述该成分发挥核心功效的生化路径，每步标注关键分子/酶/受体/反应。
   如该成分有多条作用路径，每条路径单独描述。
   标注支撑每步机制的文献来源（PMID）。

2. **竞品机制对比表**（至少 5 种同功效的已上市/主流成分）：
   | 成分 | 作用机制 | 作用阶段 | 优势 | 劣势 | 来源 |
   表格下方写 1-2 段对比分析，明确该成分的差异化定位。
   从 T6 补充竞品的详细信息，确保对比全面。

3. **配方条件要求**（如适用）：
   从 T10 提取该成分发挥活性所需的 pH、温度、辅因子、浓度范围，组织为表格。
   如成分无需特殊条件，写"无特殊配方要求"并简述原因。

4. **近 3 年研究突破**（如有）：
   从 T2 中检索近 3 年的研究进展，每项突破写 3-5 句描述，标注 PMID。
   如无近 3 年突破，标注"该领域近 3 年无重大突破"。

##### 第四节：临床证据

读取：`drafts/T04_临床证据.md`

**分析深度：**

1. **临床研究一览表**：
   列出 T04 中检索到的全部已发表临床研究（表格）：
   | # | 研究名称 | 执行机构 | 地区/年份 | 证据等级 |
   无临床研究则标注"未检索到已发表临床研究"，并说明这是市场空白还是研究空白。

2. **每项同行评审研究的详情**：
   对 T04 中标注"置信度：高"的每项研究，单独展开：
   标题、作者、期刊、PMID/DOI、研究设计、样本量、时长、分组、主要结果（包含量化数据）、结论、局限性。
   标注 `⭐ 可跳转` 并附 PubMed 链接。
   **不要只写一行摘要——每项研究需要完整的上述信息。**

3. **商业/未发表数据**（如有）：
   T04 中来自品牌新闻稿或商业材料的临床数据，单独列为一节，开头标注：
   "以下数据来源为利益相关方，未经独立同行评审，置信度：低"。
   不得与同行评审数据混为一谈。

4. **系统综述引用**（如有）：
   如 T04 中包含系统综述或荟萃分析，单独列出，说明其对该成分的证据等级评价。

5. **证据总结表**：
   用表格对每条核心论断给出证据状态判断：
   | 论断 | 有无证据支撑 | 证据类型 | 来源 |
   例如："美白效果有 RCT 支撑"→ ✅；"效果优于氢醌"→ ❌（疗效相当，非全面超越）；
   "有独立复现数据"→ ❌（仅单一团队）。不得将无证据的论断写成确定性结论。

##### 第五节：学术文献支撑

读取：`drafts/T04_临床证据.md` + `drafts/T02_作用机理.md`

**分析深度：**
- 汇总全部相关 PubMed 论文（表格）：| # | 论文标题 | 期刊 | 年份 | PMID | 关键结论 |
- 包含临床研究论文和机制研究论文。
- 每篇标注 PMID，无 PMID 的不列入此表（在正文中以其他方式引用）。

##### 第六节：竞争格局与产品现状

读取：`drafts/T05_商业化现状.md` + `drafts/T06_竞争格局.md` + `drafts/T07_用户体验.md`

**分析深度：**

1. **主要产品表格**：
   从 T5 提取使用该成分的全部已知品牌/产品：
   | 产品名 | 品牌 | 规格 | 功效宣称 | 市场状态（活跃/退出/萎缩） | 来源 |

2. **价格体系**：
   从 T5 提取不同市场/渠道的价格数据，组织为表格。
   如价格数据稀疏，标注"该成分产品定价信息有限"。

3. **竞品对比分析**：
   从 T6 提取同功效主流成分的对比，包含：
   - 机制对比（已在第二节完成的可引用，此处聚焦市场份额/渗透率/消费者认知度对比）
   - 该成分的差异化定位（2-3 段分析）

4. **用户体验汇总**：
   从 T7 提取消费者评价：
   - 正面反馈（分类列出高频词/典型原文）
   - 负面反馈（分类列出高频词/典型原文）
   - 数据来源和时效性标注

5. **品牌现状评估**：
   综合以上信息给出判断：正面信号 / 负面信号 / 综合判断。
   判断必须基于具体事实（如"官网已下线"、"Amazon 仅剩历史库存"），而非泛泛描述。

##### 第七节：监管状态

读取：`drafts/T08_监管状态.md`

**分析深度：**

1. **逐市场覆盖**（以下 5 个市场必须全部写到，无数据也要标注）：

   每个市场写：
   - 主管机关
   - 监管框架（正面清单制 / 禁用清单制 / 企业自评）
   - 该成分在对应数据库中的查询结果
   - 准入路径（可直接使用 / 需注册 / 需备案 / 禁用）
   - 准入门槛评估（高 / 中 / 低）及理由
   - 相关新规或政策变化（如有）

   | 市场 | 监管方式 | 成分状态 | 准入门槛 | 关键卡点 |
   |------|----------|----------|----------|----------|
   | 中国 NMPA | ... | ... | ... | ... |
   | 韩国 MFDS | ... | ... | ... | ... |
   | 美国 FDA | ... | ... | ... | ... |
   | 欧盟 CosIng | ... | ... | ... | ... |
   | 日本 MHLW | ... | ... | ... | ... |

2. **准入路径建议**（如适用）：
   如该成分在某些市场需要注册/备案，描述具体合规路径、预估周期、关键卡点。

##### 第八节：数据库查询指南

读取：`drafts/T08_监管状态.md`

**分析深度：**
- 各官方数据库的查询结果（表格）：| 数据库 | 网址 | 查询结果 |
- 记录实际查询过程和结果，方便用户复现验证。

##### 第九节：商业化机会与风险评估

读取：`drafts/T05_商业化现状.md` + `drafts/T06_竞争格局.md` + `drafts/T08_监管状态.md` + `drafts/T09_公司关系.md`

**分析深度：**

1. **机会分析**（3-5 个具体机会点）：
   每个机会点写：机会描述 + 支撑证据 + 来源。
   不要泛泛写"市场潜力大"，要写"XX 市场无竞争产品（来源：T5/品牌调研）"。

2. **风险分析**（3-5 个具体风险点）：
   每个风险点写：风险描述 + 影响程度 + 来源。
   包含监管风险、技术风险、商业风险、数据风险等维度。

3. **适合进入的公司类型**：
   明确指出什么类型的公司适合进入（如"有韩国渠道的公司"、"有生物催化技术背景的公司"），
   每种类型写明理由和前提条件。

##### 第十节：待验证事项

读取：全部 Thread 文件的"数据缺口"或"待验证"部分。

**分析深度：**
- 编号列表，列出所有无法在本次调研中确认的事项。
- 每条注明：事项描述 + 所属维度 + 建议的验证方式（如"联系供应商确认"、"查询 NMPA 数据库"）。

##### 第十一节：参考文献

读取：全部 Thread 文件的来源标注。

**分析深度：**
- 编号列表，汇总所有引用的 PMID、专利号、URL、新闻源。
- 每条包含：编号 | 类型（论文/专利/官方/新闻）| 引用内容 | 链接/编号
- 无死链——URL 类来源需确认可访问。

#### 写作规则

1. **结论先行**：每段先给判断，再给证据。
2. **来源必标**：每条事实标注 `[PMID xxxxxxxx]`, `[EPO patent]`, `[SEC EDGAR, date]`, `[press release, date]`。
3. **证据分级**：区分 ✅ Peer-reviewed (PMID) / 📋 Commercial materials / 🔍 Unverified claims。
4. **不确定性透明**：`⚠️ 待核实`, `（未公开披露）`, `（根据XX推断）`。
5. **表格优先**：结构化数据用表格，分析叙述用文字。
6. **中立语气**：不使用品牌营销语言。
7. **零废话**：删掉所有不增加信息量的句子。但"零废话"不等于"不写叙述"——分析判断、对比、因果推理都是信息量。

#### 增量保存

- 每完成一个主要章节 → 保存 `report.md`
- 用户每次修正后 → 立即保存
- QA 前保存一份备份到 `drafts/`

文件命名：

## 修改原则

修改报告时严格执行：

1. **先读再改**：读取现有文件，精确匹配文本。
2. **定点修改**：section by section，绝不全文重生成。
3. **批量替换**：同一 PMID/关键词在全文多处出现时，用 Python：
   ```python
   content = open(md_file, 'r', encoding='utf-8').read()
   content = content.replace('OLD', 'NEW')
   open(md_file, 'w', encoding='utf-8').write(content)
   ```
4. **保存即存**：每次修改后立即保存。

## 红线

出现以下任一情况，应回退到相应阶段重做：

- 未做 web research 就写报告。
- 证据未搜全就开始撰写。
- 使用无 PMID、无专利号、无官方 URL 的来源支撑关键判断。
- 以品牌宣传材料为准而非 EPO/官方数据库。
- 数据薄弱却写成确定性结论。
- 引用数据不标注来源。
- 报告内部存在未解决的矛盾（如某节说"产品在市"另一节说"品牌退出"）。
