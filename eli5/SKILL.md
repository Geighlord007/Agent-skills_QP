# eli5

Explain like I'm someone who knows nothing about this topic, using a HTML
artifact with big pictures and few words.

> **名字里的 "5" 只是触发钩子，不是写作指令。** 正文口径是「对这个话题一无所知的人」——
> 真按五岁词汇量写，准确率会垮，上游原作者是刻意把正文改成这个说法的。
> 本技能的默认档 = **聪明的零基础成年人**，不是五岁小孩。

## 第 0 步：先问受众（强制）

**先问，再画。** 除非用户在本次请求里已经明确说了受众（"给我 5 岁女儿讲" / "给 CTO 看"），
否则先用 `ask_user_question` 问一句，拿到答案再动手画。

| 档位 | 读者是谁 | 语言策略 | 类比取材 | 篇幅 / 深度 |
|---|---|---|---|---|
| **儿童** | 5–10 岁 | 零术语，短句，一句一个意思 | 玩具、动物、糖果、游乐场 | 很短，一概念一张图 |
| **零基础成年人** ⭐默认 | 聪明，但不懂这一行 | 术语首次出现必须当场解释 | 快递、邮局、餐厅点单、日常琐事 | 中等，讲清"是什么 + 为什么" |
| **同行 / 工程师** | 懂技术，不懂这道题 | 直接用术语，不解释基础词 | "像个 hash map，但……" | 重点讲 trade-off、边界、设计取舍 |
| **决策者** | 老板 / 客户 / 投资人 | 不出现实现细节 | 花钱、排期、下注、买保险 | 只讲影响、成本、风险、要拍什么板 |

- 问的时候把 **零基础成年人** 标成推荐项。
- 用户答"随便 / 你看着办 / 你定" → 用**零基础成年人**档。

## 产物纪律

- **HTML 里不许出现任何受众标签。** 禁用："五岁小孩都能懂"、"小白友好"、"简单来说"、"用人话讲"——
  这种话等于当着读者面说"我默认你很笨"，给同事或老板看会很尴尬。
- **结尾一句话收束**，用中性表述：「**一句话记住它**：……」+ 一个比喻。
- 一份产物只服务一个档位。需要两档就出两个文件。

## 输出约定（DSH 适配）

- 写一个**自包含的单文件 HTML**（内联 CSS/SVG，不引外部资源），保存到会话工作区，文件名如 `eli5-<topic-slug>.html`。
- 若本会话环境有媒体输出目录（如 `lark-workspace/media`）且用户在用聊天通道，可同时把该文件作为产物回复给用户；否则给出文件路径即可。
- 如果主题是当前代码库里的东西（某个模块/决策/incident），先用 read/grep 读真实代码与证据再画，不要凭空编造。

## 画法要求（就是那 26 个词的精髓）

- **受众钉死**：按第 0 步选定的档位写。不从术语开始，从生活类比开始——**类比的取材随档位变**（给工程师讲别用糖果打比方，给决策者讲别画数据库表）。
- **格式钉死**：big pictures, few words。几张卡片，每张一幅大图（SVG/CSS 画的示意图，不是装饰插画）配一句话；禁止输出长段落作文。
- **载体钉死**：HTML。布局、颜色、SVG 都能塞进去，方便截图、分享、存档。
